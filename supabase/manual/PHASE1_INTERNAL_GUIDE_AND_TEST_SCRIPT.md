# คู่มือภายใน Phase 1 + สคริปต์ทดสอบรอบสุดท้าย (รุ่งฟ้า CRM)

> **Stage 52A-16** — เอกสารสำหรับเจ้าของระบบ / admin / พนักงาน ก่อนเริ่มทดสอบจริง 2–3 คน
> ไฟล์นี้เป็นเอกสารอย่างเดียว — ไม่มี SQL ไม่มีคำสั่งลบข้อมูล

---

## 1. สถานะ Phase 1 ตอนนี้

**พร้อมใช้แล้ว ✅**
- ลูกค้า: เพิ่ม/แก้/นำเข้า ผ่านประตู server (RPC) — browser เขียนตารางตรงไม่ได้แล้ว
- เอกสาร: อัปโหลด/เปิดดู/แก้ข้อมูล ผ่านประตู server — ปิดเขียนตรงแล้ว
- คำขอลบแบบควบคุม: พนักงานส่งคำขอ → admin อนุมัติ → ระบบถึงลบจริง
  (ลูกค้า = ซ่อนถาวรแบบเก็บหลักฐาน, เอกสาร = ลบรายการ)
- ประวัติการใช้งาน (audit log) + ประวัติ login (IP / อุปกรณ์ / เบราว์เซอร์)
- นายจ้าง/กลุ่มงาน: เขียนผ่าน RPC + ปิดเขียนตรงแล้ว
- ปุ่มตรวจสุขภาพระบบ (readiness checker) ในหน้า ตั้งค่า — ต้องผ่านทุกข้อ
- Badge/แดชบอร์ด/มือถือ/นำเข้า-ส่งออก ตรวจและแก้ครบแล้ว
- แผนล้างข้อมูลทดสอบ + แผนจัดการบัญชี (ไฟล์ TEST_DATA_RESET / FINAL_ACCOUNT ในโฟลเดอร์นี้)

**พักไว้ก่อน ⏸️ (ตั้งใจ — อย่าเพิ่งไปแตะ)**
- ระบบตอกบัตร (attendance): ใช้งานพื้นฐานได้ แต่การ harden จริงเลื่อนไปหลัง Phase 1
- แจ้งเตือน LINE ตอกบัตร: พักไว้ (โควต้าฟรี/ค่าใช้จ่ายรายเดือน)
- Meta Ads: ไม่อยู่ในขอบเขต Phase 1

**ห้ามแตะ ⛔**
- ข้อมูล **เอกสารจาก LINE (line_file_inbox)** — ห้ามลบ/ห้ามล้าง
- Migrations / RPC / สิทธิ์ความปลอดภัยที่ติดตั้งแล้ว
- อย่ารัน SQL ลบข้อมูลใด ๆ นอกไฟล์ manual ที่มีขั้นตอน dry run กำกับ

## 2. กติกาบัญชีผู้ใช้

- **Admin**: ดูแลระบบ อนุมัติคำขอลบ ดู security log — *ไม่ต้อง* ผูกกับพนักงานตอกบัตร
- **Staff**: **username ต้องตรงกับ "รหัสพนักงาน" (employee_code)** ในเมนูจัดการพนักงาน
  (สร้างพนักงานก่อน → แล้วสร้างผู้ใช้จาก dropdown พนักงาน ระบบเติม username ให้เอง)
- ใช้ **ตัวพิมพ์เล็กล้วน** เช่น `leejunki` / `rungfa` / `fon` / `namfon`
  (ไม่จำเป็นต้องเป็น EMP001 — ระบบรับชื่อ login ธรรมดาได้)
- ⛔ **ห้ามลบ/ปิดใช้งาน admin ตัวจริงเด็ดขาด** — ต้องมี admin ที่ login ได้อย่างน้อย 1 บัญชีเสมอ
- บัญชีทดสอบเก่า (EMP001–005, RF001–002): **ปิดใช้งานก่อน** (ย้อนกลับได้)
  ลบถาวรทีหลังเมื่อแน่ใจแล้วเท่านั้น — ดูไฟล์ `FINAL_ACCOUNT_TEST_USER_CLEANUP_REVIEW_ONLY.sql`

## 3. ทดสอบงานลูกค้า

| # | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| 3.1 | เพิ่มลูกค้าใหม่ 1 คน | บันทึกได้ ขึ้นในรายชื่อ ตัวเลข badge อัปเดต |
| 3.2 | แก้ไขข้อมูลลูกค้า (สถานะ/เบอร์/นายจ้าง) | บันทึกได้ ข้อมูลเปลี่ยนจริง |
| 3.3 | อัปโหลดเอกสาร/รูปให้ลูกค้า | อัปโหลดสำเร็จ |

| 3.6 | กดลบลูกค้า → ส่งคำขอลบ | ขึ้นข้อความ "จะลบจริงเมื่อผู้ดูแลระบบอนุมัติ" |

## 8. ทดสอบมือถือ (smoke test)

เปิดจอมือถือ (~390px) แล้วเช็ค:

- [ ] Modal (รายละเอียด/แก้ไข) เลื่อนภายในได้ ปุ่มบันทึก/ยกเลิก/ปิด กดถึง

- [ ] Security log เลื่อนซ้าย-ขวาดูคอลัมน์ IP ได้
- [ ] ปุ่มอนุมัติ/ปฏิเสธในหน้า คำขอลบ กดถึง
- [ ] แถบเมนูล่าง (bottom nav) ไม่บังปุ่มสำคัญ และตัวเลข badge ตรงกับ desktop

## 9. เรื่อง LINE inbox (สำคัญ)

- **เก็บข้อมูล เอกสารจาก LINE ไว้ทั้งหมด** — ห้าม reset/ลบ `line_file_inbox` เว้นแต่จะอนุมัติเป็นลายลักษณ์อักษรทีหลัง
- แจ้งเตือนตอกบัตรทาง LINE **พักไว้ก่อน** เพราะโควต้าข้อความฟรีมีจำกัด/มีค่าใช้จ่ายรายเดือน — ไม่ใช่ bug

## 10. แผนทดสอบจริง 2–3 คน

**ใครทดสอบอะไร**
| คน | บทบาท | ทดสอบหมวด |
|---|---|---|
| เจ้าของ/admin | admin | หมวด 2, 6, 7 (อนุมัติคำขอลบ, security log, readiness) |
| พนักงานคนที่ 1 | staff | หมวด 3, 4 (งานลูกค้า+เอกสารประจำวัน) + มือถือ (หมวด 8) |
| พนักงานคนที่ 2 (ถ้ามี) | staff | หมวด 5 (นำเข้า/ส่งออก) + ลองส่งคำขอลบ |

**หลักฐานที่ต้องเก็บ**
- Screenshot ทุกข้อที่ "ไม่ผ่าน" พร้อมเวลาที่ทำ
- Screenshot หน้า readiness checker ตอนผ่านครบ
- ไฟล์ export ตัวอย่าง 1 ไฟล์

**วิธีรายงานปัญหา** — บอก 4 อย่าง:
1. ทำอะไร (กดปุ่มไหน หน้าไหน) 2. คาดว่าจะได้อะไร 3. ได้อะไรจริง 4. มือถือหรือคอม + screenshot

**ต้องผ่านก่อนไป Phase 2**: หมวด 3, 4, 5, 6 ผ่านครบทุกข้อ / หมวด 7–8 ไม่มีปัญหาที่ขวางงานจริง

## 11. เตือนความจำก่อน Phase 2

- Phase 2 เริ่มได้เมื่อฐาน Phase 1 นิ่ง (ทดสอบจริงผ่าน + ข้อมูลสะอาด + บัญชีตัวจริงครบ)
- สิ่งที่ Phase 2 จะสร้างต่อ: โปรไฟล์นายจ้างแบบเต็ม (เลขทะเบียน/เอกสาร/ผู้ติดต่อ),
  ระบบเคส MOU / CI / Visa / Work Permit, checklist เอกสาร, วันนัด/วันหมดอายุราย
  เคส, ประวัติสถานะ, รายงานราย นายจ้าง — ทั้งหมดต่อยอดจาก ลูกค้า + นายจ้าง +
  เอกสาร + สถานะ + วันหมดอายุ ที่มีอยู่แล้วใน Phase 1
